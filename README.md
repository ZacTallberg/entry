# Greenhouse Plot Template — spin up a NEW app the right way

**The rule (ADR-template-1): a new app is born as a CLEAN Plot whose ROOT serves the app.** Never
clone-and-pivot an existing Plot — that drags the donor's landing onto your root (this is exactly what
broke openmic: it cloned homebase, so `/` served homebase's "command center" and the real app was
buried at `/mics/`, and the deployed URL was unfindable). Use `spinup.sh`.

## Spin up
```bash
bash /c/code/_template/spinup.sh <app-slug>     # e.g. widgets
cd /c/code/<app-slug>
DEBUG=1 SECRET_KEY=d python manage.py migrate && python manage.py runserver   # root = the app
```
`spinup.sh` copies the template, stamps `<app-slug>` into every `entry` marker, and leaves you a
clean Django Plot. Build your app in `app/` (`views.py`, `models.py`, `templates/app/`).

## What you get (clean, born-safe)
- **Root serves the app** — `project_site/urls.py` routes `/` → `app.urls`; the hub lives at `/hub`,
  NEVER at the front door. No `board`/command-center cruft.
- **Born-safe settings** — `SECRET_KEY` required in prod (no committed literal), `DEBUG` off by default,
  HTTPS cookies, `ALLOWED_HOSTS` from env, hub writes token-gated (`HUB_WRITE_TOKEN`).
- **migrate-on-boot** in the Dockerfile/Procfile — guarantees tables exist (prevents the `no such
  table` outage); SQLite on the `/app/data` persistent mount (WAL + busy_timeout).
- **Reusable deploy** — `deploy.sh` calls `/c/code/_deploy/offbox-deploy.sh`: build off-box, ship the
  image to the NAS, `dokku git:from-image`. A **front-door canary enforces the root renders the app**
  before declaring live. Data (sqlite) deploys separately (scp → storage → restart).
- **`plot.toml`** manifest — the homebase REGISTRY reads these to list every created Plot (task #6).

## Hub (`/hub`) — best-in-class, baked in (WIRED + tested)
Every Plot is born with the agent-operable, event-sourced hub at `/hub`:
- `hub_core/` is the portable engine (store · projections · audit · ids · validate) and renders its
  OWN UI shell (`hub_core/frontend/`) — no Django templates.
- `hub/` is the thin clean surface (app-name `hub`, NOT `board`; NO home view at root): `hubsite.py`
  (`shell.render`), `hub_api.py` (read JSON), `hub_write.py` (token-gated writes via `X-Write-Token`),
  `urls.py`, and the `manage.py` commands `seedhub` (genesis from `PROJECT/seed.json`) + `hubaudit`
  (the born-safe invariant GATE, run by `deploy.sh`).
- `PROJECT/schema/` holds the entity schemas; `PROJECT/.hub/` is the per-app event log (regenerated by
  `seedhub`, not copied at spin-up). Edit `PROJECT/seed.json` to set your project's genesis tasks/ADRs.

## The Project Plane (`PROJECT/`) — the management framework, baked in (ADR-template-2)
Every Plot is born with the full content-agnostic PM framework — **`PROJECT/README.md` is the spec
and the map**. The spine: `HANDOFF.md` (resume here) · `CHARTER.md` (mission/DoD) · `DOCTRINE.md`
(standing laws) · `ADR/` (decisions) · `research/` (the WHY) · `registers/` (failure-modes,
incidents, truth matrix, blind spots, pending decisions, glossary) · `audit/` + `verify/` + `runs/`
(audit history + fail-closed gates) · `worklogs/` + `ops/` · `pm/PROTOCOL.md` (the
leader/worker/verifier multi-agent campaign law, dormant until a campaign activates). Crystallized
2026-07-02 from the everyopenmic campaign + the greenhouse doctrine corpus.

**Porting the Plane to a fresh environment (no files needed): hand `PROJECT-PLANE-BOOTSTRAP.md`
to the new agent** — a fully self-contained spec (laws + entity model + all 33 templates/schemas
embedded verbatim + substrate contract + bootstrap procedure + setup self-test). Regenerate/verify
the embeds with `python tools/build_bootstrap.py [--check]` whenever templates change.
